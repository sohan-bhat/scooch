Everything new since 0.1.2. All four changes are for Linux. On macOS and Windows 0.1.3 works as 0.1.2 does.

Linux

- On GNOME a picture picked in the desktop's own settings now always reaches the screen. In 0.1.2 GNOME Shell could go on showing the older Scooch picture after a pick, until the next icon move. The picture file now takes a new name each time Scooch writes the background settings, so GNOME Shell loads the new file.
- Turning Scooch off gives back the picture picked last. In 0.1.2 a picture picked in the desktop's own settings while Scooch was on was lost at the next off, and the desktop showed the picture from before Scooch.
- Closing the window frees the window's memory. In 0.1.2 the process behind the tray icon kept 137 to 160 MB after a window had been open, with 22 threads and about 15 wakeups a minute. Now a fresh process takes over the icon at each close and holds 28 to 30 MB in 9 threads with no wakeups, measured on Xfce 4.18. At each close the tray shows no Scooch icon for under a tenth of a second. The next window opens after 0.1 to 0.3 s where 0.1.2 took about 0.05 s.
- An X display that stops answering can no longer pile up threads. After four reads with no answer, each further read ends at once.

Downloads

- macOS on Apple silicon and Intel, `Scooch.dmg`
- Windows on x64 or Arm, `Scooch-Setup-x64.exe` or `Scooch-Setup-arm64.exe`
- Linux as a deb, `scooch_amd64.deb` or `scooch_arm64.deb`
- Linux as an rpm, `scooch.x86_64.rpm` or `scooch.aarch64.rpm`
- Linux as an AppImage, `Scooch-x86_64.AppImage` or `Scooch-aarch64.AppImage`

On macOS the app is not notarized, so the first open needs Open Anyway in System Settings under Privacy and Security.

On Windows the setup is not signed, so SmartScreen shows a warning the first time.

The command alone on macOS and Linux

```sh
curl -LsSf https://sohanbhat.me/scooch/install.sh | sh
```

The command alone on Windows

```powershell
irm https://sohanbhat.me/scooch/install.ps1 | iex
```
